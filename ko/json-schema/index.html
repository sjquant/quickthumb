    JSON Schema와 AI 작업 흐름

    quickthumb의 모든 캔버스는 JSON으로 작성할 수 있습니다. LLM이나 템플릿으로 생성하고 데이터베이스에 저장하거나 API로 보내거나 콘텐츠와 함께 버전 관리할 수 있습니다.

    첫 명세를 생성·검증·렌더링하려면 AI 작업 흐름을 따르세요. 이 문서는 레이어 필드, 효과, 공개 스키마를 찾아볼 때 사용합니다. quickthumb 명령에는 pip install "quickthumb[cli]"가 필요하지만 Python 스키마 도우미는 CLI 추가 기능 없이도 동작합니다.

    왕복 직렬화

    정규 JSON은 내보낸 결과물이 아니라 작성한 문서 자체를 저장하는 형식입니다.

    from pathlib import Path

from quickthumb import Canvas

# Python → JSON
canvas = Canvas(320, 180).background(color="#102030")
json_str = canvas.to_json()
Path("scene.json").write_text(json_str, encoding="utf-8")

# JSON → Python
restored = Canvas.from_json(Path("scene.json").read_text(encoding="utf-8"))
assert restored.to_json() == json_str
restored.export("from-json.png")

    참고

    Canvas.from_json()은 JSON 문자열을 받습니다. Python dict가 있다면 먼저 json.dumps(data)를 호출하세요. Python 함수를 JSON에 저장할 수 없으므로 .custom(fn) 레이어가 있는 캔버스는 직렬화할 수 없습니다.

    같은 문서를 해석해 정규 JSON으로 저장하면 항상 같은 결과를 얻습니다. 다만 글꼴, 이미지, 미디어, 캐시에 내려받은 파일까지 함께 묶어 주지는 않습니다. 참조 파일을 보관하고 다른 환경에서 렌더링할 때도 해당 경로로 접근할 수 있게 해 주세요. 플러그인 JSON도 Python 콜백이 아닌 선언된 매개변수와 에셋 참조를 유지하므로 불러올 때 대응하는 명시적 레지스트리를 제공하세요. 장면 JSON이 같아도 글꼴, 렌더러 버전, 플랫폼이 다르면 같은 픽셀을 보장하지 않습니다.

    JSON 구조

    Canvas JSON 문서는 최상위 필수 필드 네 개와 선택적인 theme 블록을 가집니다.

    {
  "kind": "canvas",
  "width": 1280,
  "height": 720,
  "theme": { ... },
  "layers": [ ... ]
}

    Canvas.from_json(), Deck.from_json(), CLI에는 최상위 "kind" 구분자가 필수이며 값은 "canvas" 또는 "deck"여야 합니다. Canvas는 layers, Deck은 slides를 포함하며 Deck은 공통 기본 크기, 테마, 전환도 정의할 수 있습니다. 각 레이어 객체에는 자체 "type" 구분자가 필요합니다. 레이어는 배열 순서대로 그리며 첫 항목이 맨 뒤입니다. 레이어 ID, 배치, 정렬, 모션은 Python, Canvas JSON 루트, 모든 Deck 슬라이드에서 같은 공통 용어를 사용합니다. Deck이 별도 레이어 스키마를 도입하지는 않습니다.

    공개 스키마

    Canvas.from_json()과 같은 Pydantic 모델에서 현재 JSON Schema를 출력합니다.

    quickthumb schema > quickthumb.schema.json
quickthumb schema --output quickthumb.schema.json
quickthumb schema --document --output quickthumb.document-schema.json

    같은 스키마를 Python의 canvas_json_schema(), document_json_schema()로 얻을 수 있으며 이 문서와 함께 다음 주소에도 제공합니다.

    • https://quickthumb.solaqua.dev/schema.json (Canvas)
    • https://quickthumb.solaqua.dev/document-schema.json (Canvas 또는 Deck)

    VS Code에서 명세를 편집할 때 자동 완성과 검증을 사용하려면 .vscode/settings.json에 명세 파일과 공개 스키마의 매핑을 추가하세요.

    {
  "json.schemas": [
    {
      "fileMatch": ["*.thumb.json"],
      "url": "https://quickthumb.solaqua.dev/schema.json"
    }
  ]
}

    명세 안의 "$schema" 키 대신 이와 같은 파일 매핑을 사용하세요. Canvas.from_json()은 $schema를 포함한 알 수 없는 최상위 필드를 거부합니다.

    호스팅 파일은 main 브랜치를 따르는 문서 배포마다 다시 생성됩니다. 설치한 버전의 스키마는 quickthumb schema로 얻으세요.

    스키마 범위

    quickthumb schema는 외부 도구와 제약된 생성에 사용할 구체적인 Canvas 명세를 설명합니다. 결합된 Canvas/Deck 구분자 스키마에는 quickthumb schema --document를 사용하세요. 실제로 불러올 수 있는 내용의 기준은 Canvas.from_json()입니다.

    CLI, serve, Canvas.from_json(), Deck.from_json()에는 모두 맞는 최상위 kind 구분자가 필요합니다. 새로 직렬화한 문서는 Deck 슬라이드를 포함해 모든 문서 경계에 구분자를 포함합니다.

    Deck이 기본 크기를 제공하면 슬라이드의 width, height는 생략할 수 있습니다. 문서 스키마도 이를 허용하고 정규 JSON은 각 슬라이드에 상속된 크기를 출력합니다. 전환 객체는 Deck.from_json()과 같은 엄격한 구분자 계약을 사용합니다.

    $theme.* 같은 제작 편의 기능은 모델 검증 전에 quickthumb가 해석합니다. 따라서 quickthumb가 불러올 수 있는 미해결 제작 명세도 일반 JSON Schema 검증기는 거부할 수 있습니다.

    명령은 결정적인 JSON만 출력하므로 저장소에 넣거나 편집기로 파이프하거나 제약된 생성 API에 직접 전달할 수 있습니다. Canvas 스키마에는 현재 캔버스 필드, 내장 레이어 구분자, 효과, 애니메이션, 지원 플랫폼 프리셋, 선택적인 최상위 theme가 포함됩니다. --document 스키마는 Deck 루트를 추가하고 kind로 두 문서 종류를 매핑합니다.

    플러그인 레이어

    플러그인은 하나의 명시적인 PluginRegistry에 등록합니다. 등록은 레이어 종류와 매개변수를 설명하며 신뢰할 수 있는 별도의 동기식 raster 콜백이 정규 RGBA 픽셀로 렌더링합니다. 콜백은 애플리케이션 코드이며 JSON으로 직렬화하거나 JSON에서 가져오지 않습니다.

    from quickthumb import Canvas, PluginRegistry, canvas_json_schema

registry = PluginRegistry()
registry.register(
    "brand_badge",
    "1.0",
    params_schema={
        "type": "object",
        "required": ["label"],
        "properties": {"label": {"type": "string"}},
        "additionalProperties": False,
    },
)

canvas = Canvas.from_json(text, registry=registry)
schema = canvas_json_schema(registry=registry)

    플러그인 레이어에는 type: "plugin", renderer, version, 객체형 params, 양의 정수 width/height가 필요합니다. position은 일반 픽셀·백분율 좌표를 받으며 align, opacity는 로컬 상자에 적용됩니다. 렌더링 후 표준 clip, mask 경계를 적용합니다. Group은 자식 위치를 정하고 정적 플러그인 픽셀을 포함한 그룹 전체를 애니메이션화할 수 있습니다. 문서 파서와 Schema 도우미에 같은 명시적 레지스트리를 제공해야 합니다.

    from PIL import Image

def badge(params, context):
    with Image.new("RGBA", context.size, params["color"]) as image:
        return image.tobytes()

registry.register("badge", "1", raster=badge)
canvas = Canvas(320, 180, registry=registry).plugin(
    "badge", version="1", params={"color": "#42CEB7"},
    position=(20, 30), width=120, height=40,
)
canvas.export("badge.png")

    raster 콜백은 params dict와 context.size를 받고 원시 RGBA8 바이트(width * height * 4)를 반환합니다. 레이어의 assets={"texture": "assets/texture.png"}로 외부 에셋을 선언하고 context.read_asset("texture")로 접근하세요.

    선택적인 네이티브 SVG

    벡터 출력에는 SVG 문자열을 반환하는 선택적 svg= 콜백을 등록합니다.

    def badge_svg(params, context):
    width, height = context.size
    return (
        f'<svg xmlns="http://www.w3.org/2000/svg" width="{width}" height="{height}">'
        f'<rect width="{width}" height="{height}" fill="{params["color"]}"/></svg>'
    )

registry.register("badge", "1", raster=badge, svg=badge_svg)

    네이티브 SVG 플러그인을 지원하지 않는 형식에서는 자동으로 raster 콜백 렌더링으로 대체합니다.

    플러그인 params Schema v1

    params_schema는 문서화된 quickthumb plugin-params v1 부분집합을 받습니다. JSON 자료형 object, array, string, number, integer, boolean, null과 required, properties, additionalProperties, items, const, enum, oneOf, anyOf, 문자열 패턴·크기 제한, 숫자 최솟값·최댓값을 지원합니다. $ref, allOf, not 같은 미지원 키워드는 등록 시 거부해 공개 Schema와 런타임 검증이 일치하도록 합니다.

    공통 기본값을 원하는 애플리케이션을 위해 프로세스 전역 plugin_registry도 유지합니다. 테스트, 서비스, 라이브러리는 등록을 격리하고 재현할 수 있도록 명시적 PluginRegistry를 권장합니다.

    스키마로 출력을 제한하는 생성 기능을 사용할 때는, 자료형이 정해진 필드에 토큰 대신 실제로 해석된 값을 넣으세요.

    Use quickthumb.schema.json as the JSON response schema.
Generate one valid quickthumb canvas spec for a 1280x720 YouTube thumbnail.
Return only the JSON object.
Use concrete hex colors and numeric sizes in layer fields.
Use only these layer type discriminators: background, text, image, shape, svg, group, outline.

    테마 토큰

    최상위 theme 블록에 브랜드 토큰을 한 번 정의하고 명세 어디에서든 $theme.path로 참조합니다.

    {
  "kind": "canvas",
  "width": 1280,
  "height": 720,
  "theme": {
    "colors": { "primary": "#B8FF00", "ink": "#111111" },
    "sizes": { "title": 96 }
  },
  "layers": [
    { "type": "background", "color": "$theme.colors.ink" },
    { "type": "text", "content": "Hello", "size": "$theme.sizes.title", "color": "$theme.colors.primary" }
  ]
}

    규칙은 다음과 같습니다.

    • theme는 그룹을 자유롭게 중첩할 수 있습니다. 참조 경로는 $theme.colors.primary처럼 점으로 구분합니다.
    • 문자열 전체가 참조이면 원래 JSON 자료형을 유지합니다. "size": "$theme.sizes.title"은 숫자 96으로 해석되며 토큰은 목록도 가질 수 있습니다.
    • 스칼라 토큰(문자열, 숫자)은 더 긴 문자열 안에 삽입할 수도 있습니다.
    • 테마 값이 다른 토큰을 참조하는 별칭도 가능합니다. 순환 참조는 ValidationError를 발생시킵니다.
    • 정의하지 않은 토큰 참조는 ValidationError를 발생시킵니다.
    • 토큰은 파싱 시 해석됩니다. to_json()은 theme 없이 실제 값을 출력합니다.
    • 테마 토큰은 $var 템플릿 치환(quickthumb render --var KEY=VALUE)과 함께 동작하며 $theme.*는 절대로 변수로 처리하지 않습니다.

    레이어 스키마

    자주 사용하는 레이어는 아래와 같습니다. 동영상, 차트, QR 코드, 카운터, 플러그인도 같은 패턴을 따릅니다. 필드는 공개 스키마와 각 API 레퍼런스에 있습니다.

    배경 레이어

    {
  "type": "background",
  "color": "#0F172A",
  "gradient": null,
  "image": null,
  "opacity": 1.0,
  "blend_mode": null,
  "fit": null,
  "effects": []

    그룹 레이어

    자식을 측정해 행이나 열로 쌓는 자동 레이아웃 컨테이너입니다. 따라서 자식은 position을 설정하면 안 됩니다. 그룹 레퍼런스를 참고하세요.

    {
  "type": "group",
  "direction": "column",
  "gap": 24,
  "padding": 0,
  "position": ["8%", "50%"],
  "align": ["left", "middle"],
  "item_align": "start",
  "children": [
    { "type": "shape", "shape": "pill", "width": 120, "height": 36, "color": "#E94560" },
    { "type": "text", "content": "AUTO LAYOUT", "size": 96, "color": "#FFFFFF", "weight": 900 },
    { "type": "text", "content": "No coordinates were harmed", "size": 40, "color": "#A2A8D3" }
  ]
}
    • direction: 기본 "column" 또는 "row"
    • gap: 자식 사이 픽셀 간격. padding은 정수, [vertical, horizontal], [top, right, bottom, left]
    • item_align: 교차축 배치로 "start", "center", "end" 중 하나
    • children 종류: "text", "image", "shape", "svg", 중첩된 "group"

    효과 스키마

    효과는 각 레이어의 "effects" 배열에 들어가며 "type" 구분자를 사용합니다.

    { "type": "stroke", "width": 4, "color": "#000000" }

    { "type": "shadow", "offset_x": 4, "offset_y": 8, "color": "#000000", "blur_radius": 12 }

    { "type": "glow", "color": "#B8FF00", "radius": 16, "opacity": 0.35 }

    { "type": "filter", "blur": 4, "brightness": 0.75, "contrast": 1.1, "saturation": 0.9 }

    { "type": "background", "color": "#111827CC", "padding": [16, 24], "border_radius": 14, "opacity": 1.0 }

    { "type": "grain", "intensity": 0.12, "monochrome": true, "blend_mode": "overlay", "opacity": 1.0 }

    blend_mode는 "overlay", "screen", "multiply", "normal"입니다. 결정적인 출력에는 선택 정수 "seed"를 사용합니다.

    { "type": "duotone", "shadows": "#0A1730", "highlights": "#7FADFF", "opacity": 1.0 }

    { "type": "backdrop_blur", "radius": 24, "opacity": 1.0 }

    레이어별 지원 효과는 효과 레퍼런스에 있습니다.

    직렬화 참고

    필드 직렬화 형식
    align 문자열: "center", "top-left" 등
    blend_mode 문자열: "multiply", "normal" 등
    fit 문자열: "cover", "contain", "fill"
    position JSON 배열: [640, 360] 또는 ["50%", "50%"]
    그라디언트 정지점 ["#color", 0.0] 쌍의 JSON 배열
    null 필드 생략한 필드는 null 또는 기본값 사용
    theme 블록 파싱 시 해석되며 to_json()은 theme 없이 실제 값 출력
